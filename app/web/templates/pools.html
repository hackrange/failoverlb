How nginx picks which backend gets each request.

What you can use

  • round_robin takes turns. The default, and fine for most things where your backends are about the same.
  • least_conn sends to whichever has the fewest open connections. Better when requests take very different amounts of time, because a slow backend piles up connections and naturally stops being picked.
  • ip_hash pins a client to a backend by their address. Careful with this one: a whole office behind one NAT address all lands on the same backend.
  • hash pins on anything you name, like a cookie. Usually better than ip_hash if you need stickiness.
  • random two least_conn picks two at random and takes the less busy one. Good on very large pools where least_conn makes everything pile onto whichever server just freed up.

What is not here

least_time and sticky cookie are in the paid nginx only. For least_time, use least_conn, which tracks it closely in practice. For sticky, turn on Sticky Sessions in the pool settings and the manager builds the cookie side of it for you. See the Open Source Parity page.

Two different things watch your backends, and it helps to know which is which.

nginx does passive checks

It notices when a real request to a backend fails and stops sending traffic there for a while. That is max_fails and fail_timeout. It is all the free nginx has on its own, and the catch is that somebody had to get an error first for nginx to find out.

The manager does active checks

It reaches out to every backend on a schedule whether or not anybody is browsing the site. When one fails enough times in a row, the manager rewrites the upstream with that server marked down and reloads nginx. So a dead backend is out of the rotation before a user ever hits it. This is the paid version's headline feature, done from out here instead of inside nginx.

Rise and fall

Fall is how many checks in a row have to fail before a backend is taken out. Rise is how many have to pass before it goes back in. Both are there so one dropped packet does not cause a reload. Higher fall means slower to react but fewer false alarms. 3 is a sensible starting point at a 10 second interval, so a backend is out within 30 seconds.

The safety net

If every member of a pool would be marked down at once, the manager leaves them all in instead and logs a warning. A pool serving errors is bad, but a pool serving nothing because a network blip failed every check at the same moment is worse.
