Slows down a client asking for too much, too fast.

The two pieces

A zone says what to count and how fast is allowed. It is shared, so several sites can draw on the same bucket. Then a site or a path points at it, and that is where you set the burst. Almost always you count per client address, using $binary_remote_addr. It is the packed form, which takes a quarter of the memory of $remote_addr, and that matters when the zone is holding a million of them. 10m of zone holds roughly 160,000 addresses.

Reading the rate

10r/s does not mean ten in any given second. nginx uses a leaky bucket, so it means one every 100ms. Two requests back to back and the second is already over, even though you are nowhere near ten that second. Real browsers fire a dozen requests at once for one page. That is why the burst on the site matters: without it, a completely normal page load gets a 503.

Sensible values

  • 5r/m on a login endpoint. Nobody logs in twelve times a minute honestly, and it makes password guessing pointless.
  • 10r/s to 30r/s for a general site or API.
  • Give each a separate zone so a burst of API traffic cannot use up the allowance that was protecting your login page.

Caps how many connections one client can hold open at the same time.

Different from rate limiting

Rate limiting counts requests over time. This counts connections right now. It is the right tool for downloads. Somebody pointing a download manager at your files opens thirty connections and eats your uplink without breaking any request rate limit at all, because they are not making many requests, just very long ones.

Do not set it too low

Browsers routinely open six connections to one host. Anything behind an office NAT or a mobile carrier has many real people on one address. Set it to 2 and you will break an entire office and never hear a useful bug report about it. 10 to 20 is sensible for a normal site. Save the low numbers for a downloads path.

Keeps copies of backend responses so the backend is not asked twice.

Usually the biggest speed win available

A page that takes the backend 400ms comes back in about a millisecond from cache, and the backend never sees the request. It is free and it is often the difference between needing more backends and not.

The two sizes are different things

Keys zone is memory for the index, not the content. 1m holds roughly 8,000 entries. Max size is disk for the cached responses themselves. Run out of keys zone and nginx starts evicting even with disk to spare, so if you cache a lot of small files, that number is the one to raise.

Before you turn it on

Caching a page meant for one logged in user and handing it to somebody else is a real data leak, and it is easy to set up by accident. On the site, set both "skip the cache when" and "never store when" to your session cookie. Doing only the first means the logged in user gets a fresh page and their copy still lands in the cache for the next visitor. The tool refuses to save that particular combination for exactly this reason.

A named set of allow and deny rules you can reuse across sites.

Include the cluster nodes

Leave that on unless you have a reason. It adds an allow line for every node in the fleet, generated from the roster rather than typed in, so a node you add next year lands in every list on its own. That is the bit people forget by hand, and it is how health checks end up blocked by a rule somebody wrote months earlier.

Trusting a forwarded address

Only turn that on when something you control is genuinely in front, and list those proxies. Anybody can send an X-Forwarded-For header claiming to be any address they like. Trusting it without naming the proxies means your allow list can be walked straight past by setting a header.

Basic auth

Useful on top of the address rules for a staging site or an internal tool. Be clear eyed about it: the password format nginx reads is APR1, which is a weak hash, and the password itself travels on every single request. Over https that is acceptable for keeping casual visitors out. It is not a login system and it should not be guarding anything that matters on its own.
