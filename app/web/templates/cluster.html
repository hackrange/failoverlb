One node is active and takes the changes. The rest are standby, stay in sync, and are ready to take over.

Why not let every node take changes

Two people editing the same site on two nodes at once gives you two different answers and no way to tell which is right. Load balancer config is not something you want to merge and hope. One writer means there is always exactly one truth.

How the active one gets picked

Highest priority among the nodes that are answering. A tie breaks on the node name, so the answer is the same every time and never a coin flip. There is one important rule on top: a node will not make itself active unless it can see more than half the cluster. In a network split the smaller side stands down. Without that, both halves would elect themselves and start writing different config to different load balancers.

What happens when a node is down

Changes still go through on the nodes that are up. The ones that are down get the change written into a queue, and when they come back the manager pushes the newest config at them and clears the backlog in one go. They never quietly drift.

Applying is two phases

Every reachable node stages the config and runs nginx -t on it first. Nothing goes live anywhere until they have all said yes. If one says no, nothing changes at all. If a node fails partway through the second phase, everything rolls back together. That is the difference between one bad config breaking one box and one bad config breaking your whole edge.
