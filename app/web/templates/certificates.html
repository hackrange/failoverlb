How this works in a cluster

Only the node that currently owns the public address for a domain can answer an http challenge, and which node that is changes when you fail over. So the manager works it out fresh every time, rather than assuming whoever did it last time can do it again. Click the ? for the details, or Where? on a certificate to see the reasoning for that one.

Getting a certificate onto several load balancers is more awkward than it looks, and this is the part that makes it work.

The problem

Lets Encrypt proves you own a domain by connecting to whatever address that domain points at. In a two node setup only one of those boxes is on the end of that address at any moment. Run certbot on the other one and the challenge fails every single time, and the error looks like a DNS problem even though DNS is fine. Worse, the node that owns the address is not fixed. Failover moves it. A certificate issued from lb-01 three months ago may need to renew from lb-02 today.

What we do

  • Look the domain up against public resolvers, not this box's own resolver, because an internal resolver often gives a private answer that is not what Lets Encrypt will see.
  • Compare that against each node's detected public address, and against the addresses actually sitting on their interfaces, which catches a floating VIP.
  • Give the job to whichever node matches.
  • Push the challenge token to every node before validation starts, so it does not matter which one gets connected to.
  • Copy the finished certificate to every node, because they all serve the same sites.

Renewals

The manager schedules these itself, and the installer turns off the certbot timer on purpose. The stock timer fires on every box, and on a node that does not own the address it fails every time. You end up with a mailbox full of failures from two of your three nodes and the real problem buried somewhere in there.

When http will not work at all

If the domain points at a cloud load balancer or a CDN rather than at your nodes, no http challenge can reach you. Use dns-01 instead, which does not need any inbound connection and can also do wildcards.
