    The hostnames this site answers to. nginx matches the Host header against these to pick which server block handles a request.

    Examples

    • www.example.com that exact name only
    • www.example.com example.com both
    • *.example.com any subdomain
    • _ the catch all, for the default site

    Which certificate this site serves over https.

    Worth knowing

    With no certificate attached, the https server block is left out altogether. That is on purpose: nginx refuses to start at all if it finds an ssl listener with no certificate, so writing one anyway would take the whole box down rather than just this site.

    Handles any request whose Host header does not match another site.

    Why you want one

    Without a default, nginx uses whichever server block it loaded first, which is usually not what you meant and moves around as you add sites. People find your server by IP address and get a random one of your sites. A default that returns a plain 404 keeps that tidy.

    Locks this site to the management networks and the cluster nodes.

    What it writes

    An allow line for every node in the cluster plus your management networks, then deny all. The node list is generated from the roster, so a node you add later lands in here on its own.

    Two ways to drive a site, and you can switch between them.

    Generated, the normal way

    The config comes from the settings on the other tabs. Every value is checked before it is stored, the help explains what each one does, and settings your nginx cannot run are not offered. The config here is read only so you can see exactly what your choices produced.

    Hand written

    You write the whole server block. Useful for something the forms do not cover yet, or config you already have and want to bring across as is. The forms stop driving this site while it is in this mode, so the two cannot fight over the same file.

    You still cannot break the fleet

    Hand written config goes through exactly the same checks as everything else. It is tested by nginx here before it is even saved, and at apply time every node stages it and runs nginx -t before any node goes live. If one node says no, nothing changes anywhere. So the worst case is a config that refuses to save, not a fleet that stops serving.
